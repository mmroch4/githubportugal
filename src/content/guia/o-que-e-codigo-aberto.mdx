## O que é

Um projeto é de **código aberto** (_open source_, em inglês) quando qualquer pessoa pode ver, usar, alterar e distribuir o seu código-fonte. Não basta o código estar público no GitHub: é a **licença** que dá estas liberdades a quem o usa. Sem licença, o código pertence ao autor e ninguém o pode reutilizar legalmente, mesmo que o consiga ler. Falamos disso no capítulo sobre **[licenças](/guia/licencas)**.

Provavelmente usas código aberto todos os dias sem dar por isso: o Linux nos servidores, o Firefox, o VS Code, o Node.js, o Python, o React, o PostgreSQL. Em Portugal também há muitos projetos assim, criados e mantidos por programadores portugueses. Reunimos vários no **[diretório de projetos](/projetos)**.

## Porque contribuir

Contribuir para um projeto open source é uma das melhores formas de aprender e de mostrar o que sabes fazer:

- **Aprendes com código real.** Lês código escrito por outras pessoas, segues as convenções de um projeto a sério e recebes revisões de quem tem mais experiência.
- **Constróis um portefólio público.** Cada pull request aceite fica no teu perfil do GitHub e é algo que podes mostrar numa entrevista de emprego.
- **Conheces pessoas.** Mantenedores, outros contribuidores e utilizadores. Muitas oportunidades de trabalho começam numa conversa numa issue.
- **Melhoras ferramentas que usas.** Se encontraste um erro ou te falta uma funcionalidade, podes ser tu a resolvê-lo, e toda a gente beneficia.

E não precisas de ser especialista. Corrigir um erro de escrita na documentação, traduzir um texto para português, reportar um bug com bons passos para o reproduzir ou responder à dúvida de outra pessoa são contribuições tão válidas como escrever código.

## Quem faz o quê

Num projeto open source vais encontrar, normalmente, estes papéis:

- **Autor ou autora:** quem criou o projeto.
- **Mantenedores:** quem decide o rumo do projeto, revê contribuições e publica novas versões. Podes conhecer alguns mantenedores portugueses na página de **[mantenedores](/mantenedores)**.
- **Contribuidores:** qualquer pessoa que já contribuiu com algo, seja código, documentação, traduções ou testes.
- **Utilizadores:** quem usa o projeto. São muitas vezes quem encontra os bugs e sugere melhorias.

## Pequeno glossário

- **Repositório (_repo_):** a pasta do projeto no GitHub, com o código e todo o histórico de alterações.
- **Fork:** uma cópia de um repositório na tua conta, onde podes fazer alterações sem afetar o original.
- **Branch (ramo):** uma linha de desenvolvimento separada dentro do repositório, onde preparas uma alteração.
- **Commit:** um conjunto de alterações guardado no histórico, com uma mensagem a explicar o que mudou.
- **Issue:** um pedido, problema ou sugestão registado no repositório. É onde se discute o que há para fazer.
- **Pull request (PR):** um pedido para juntar as tuas alterações ao projeto. Os mantenedores revêm e decidem se as aceitam.
- **Merge:** o ato de juntar as alterações de um PR ao ramo principal.
- **Release:** uma versão publicada do projeto, normalmente com um número como `2.1.0`.
- **Mantenedor (_maintainer_):** quem tem permissões para aceitar contribuições e gerir o projeto.
